# Browser interaction strategy

## Default browser session

Use Playwright MCP as the primary browser automation capability. Prefer branded Google Chrome, visible/headed operation, and a fresh isolated session for every independent test case. The current Playwright MCP option is `--browser=chrome --isolated`; headed is its default, so do not add `--headless` unless the user requests headless execution. `--isolated` keeps session profile state in memory rather than saving it to disk. Close the browser session after each independent case so cookies and web storage do not flow into the next case. Keep all steps of one multi-step case in the same session.

Treat “Incognito,” “private,” “fresh,” or “clean browser” as a request for isolated state. This provides the testing intent of Incognito, but do not claim Chrome's native Incognito UI is active. Do not add Chrome's `--incognito` flag by default; Playwright's isolated context is the supported isolation mechanism. Do not reuse an authenticated profile unless the user explicitly asks. For requested authentication, log in within the test or use explicitly supplied storage state when supported; disclose that exception in the report.

Prefer a maximized headed window when the host supports it. A Playwright MCP config can set `launchOptions.args` to `--start-maximized` and `contextOptions.viewport` to `null` so the context follows the window size. See [Playwright MCP configuration](https://playwright.dev/mcp/configuration/options) and [Playwright launch arguments](https://playwright.dev/docs/api/class-browsertype#browser-type-launch). Playwright warns custom browser arguments can affect automation, so treat maximization as best-effort and validate it for the host/browser. If it cannot be maximized, continue in the visible window unless exact window state is part of the expected result; report the environment limitation without failing the application test. Maximized means filling the available desktop work area; fullscreen is an OS/browser mode that may hide normal window chrome and is not required. Do not require OS-level fullscreen or Computer Use to change window state.

The browser setup is external to this Skill. If the configured tool is headless, uses a different browser, reuses a persistent profile, or cannot start Chrome, report that discrepancy and follow the user's browser requirement; do not imply the default was achieved. Browser identity matters when the user specifies or tests a browser. Read [authentication guidance](authentication.md) for state reuse exceptions.

Prefer Playwright MCP's accessibility snapshot and element references for actions. Use screenshots for visual inspection and evidence, not as the primary action map. When using another browser capability, follow the same semantic approach where supported.

Find targets in this order: accessible role plus name, associated label, visible text, placeholder, stable DOM attribute, visual understanding, then coordinates as a last resort. Use the current UI state, never a selector inferred from source code. A clearly equivalent label may be used when context is unambiguous; inspect further when more than one consequential action fits.

After navigation, submission, dialog changes, or other material state changes, refresh the UI snapshot. Prefer an observable ready condition over a fixed sleep. For a transient loading state, wait and retry within a small bounded number of attempts. If the element remains absent, capture the observed state and classify it under validation policy. Do not retry indefinitely.

Common controls include text and password fields, textareas, numbers, checkboxes, radio groups, selects, comboboxes, autocomplete, date/time controls, tabs, tables, pagination, dialogs, and file controls. Use each control's semantic interaction where available. For upload, locate the correct input or drop target, attach only existing user-specified files, and verify the UI acknowledgement and expected final state. Do not infer successful storage from a tool response alone.

Track redirects and SPA changes. Obtain the **active page URL** at evidence time from the browser, such as the active-tab listing or page-context evaluation where supported. Never reuse the requested navigation URL as evidence. See [evidence policy](evidence-policy.md) for capture consistency.

Browser tools and host permissions vary. If Playwright MCP is unavailable, report `BLOCKED` or provide a plan; do not automatically switch to Computer Use. Consider Computer Use only when Playwright MCP genuinely cannot perform a required interaction, the alternative can maintain the requested browser/session constraints and URL-visible evidence, and the host provides it. If no compatible tool exists, clearly state that no UI execution occurred.
